# 遥控链路交接文档

## 1. 交接目标

遥控器通过 LoRa 同时服务两块主控。遥控器负责采集全部输入并按目标 ID 发帧；本机主控接收所有 LoRa 数据，只解析属于自己的输入，属于第二主控的帧通过 McuLink 原样转发。

第二主控的队友只需要完成三件事：

1. 将接收串口配置为 `2000000 baud、8N1`。
2. 按本文协议解析目标 ID `0x02` 的固定 9 字节帧。
3. 对右侧六个按键和五个开关实现业务逻辑，并增加通信超时保护。

## 2. 当前链路

```text
遥控器 STM32F4
  USART6，115200 baud
          |
          v
      LoRa 透明传输
          |
          v
遥控接收 STM32F103
  USART3，115200 baud
          |
          +-- target_id 0x01：本机解析到 remote_link_data
          |
          +-- target_id 0x02：USART2，2 Mbps，原帧转发
                                      |
                                      v
                                  第二主控
```

遥控器平均以 `15 Hz` 发送。每个周期先发送本机帧，再发送第二主控帧；两个帧使用相同的 `sequence`，周期结束后序号加一。

发送端和接收端都会在上电时通过 AUX 自动读取、写入并校验 E32 配置 `C0 00 06 3C 06 44`。配置阶段 MCU 串口使用 `9600、8N1`，进入透明模式后切回 `115200、8N1`；任一端配置未就绪时都不会收发控制帧。

当前相关代码：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 遥控输入 | `user/RemoteInput.c` | ADC 采样、数字输入消抖、蜂鸣器 |
| 遥控发送 | `user/Remote.c` | E32 配置、目标 ID 分包、CRC、USART6 发送 |
| LoRa 接收 | `../遥控接收/Core/Src/remote_link.c` | 按长度收流、验帧、解析 ID 1、转发 ID 2 |
| 主控转发 | `../遥控接收/Core/Src/remote_link.c` | 通过 USART2 向第二主控原帧透传 |

## 3. 输入归属

| 输入 | 硬件引脚 | 使用方 |
| --- | --- | --- |
| 左侧六键 | `PA0、PC1、PC0、PA1、PA2、PA4` | 本机主控 |
| 左、右摇杆 | `PB0、PB1、PC2、PC3` | 本机主控 |
| 左、右肩键 | `PA6、PA7` | 本机主控 |
| 本机拨动开关 | `PE0` | 本机主控 |
| 右侧六键 | `PD13、PD12、PD11、PD8、PD9、PD10` | 第二主控 |
| 第二主控开关 | `PE4、PE3、PE1、PD6、PD5` | 第二主控 |

数字输入在协议中已经统一为：`0` 表示松开或断开，`1` 表示按下或闭合。接收方不需要关心 GPIO 的低电平有效关系。

## 4. 帧格式

```text
A5 5A | target_id | type | payload_len | sequence | payload | crc8
```

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 | 2 字节 | 固定为 `A5 5A` |
| `target_id` | 1 字节 | 本机 `0x01`，第二主控 `0x02` |
| `type` | 1 字节 | 遥控输入固定为 `0x01` |
| `payload_len` | 1 字节 | 只表示 payload 长度 |
| `sequence` | 1 字节 | `0..255` 循环递增 |
| `payload` | 可变 | 由目标 ID 决定 |
| `crc8` | 1 字节 | 校验 `target_id` 到 payload 末尾 |

CRC 使用多项式 `0x07`、初值 `0x00`、不反射、无结果异或。计算长度为 `4 + payload_len`，帧头不参与校验。

```c
static uint8_t Remote_Crc8(const uint8_t *data, uint8_t length)
{
    uint8_t crc = 0U;
    uint8_t i;
    uint8_t bit;

    for (i = 0U; i < length; i++)
    {
        crc ^= data[i];
        for (bit = 0U; bit < 8U; bit++)
        {
            crc = ((crc & 0x80U) != 0U) ?
                  (uint8_t)((crc << 1U) ^ 0x07U) :
                  (uint8_t)(crc << 1U);
        }
    }
    return crc;
}
```

## 5. 第二主控接收内容

第二主控正常情况下只会收到本机主控转发的 9 字节帧：

```text
A5 5A 02 01 02 sequence key_bits switch_bits crc8
```

### `key_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PD13` | 1 为按下 |
| bit1 | `PD12` | 1 为按下 |
| bit2 | `PD11` | 1 为按下 |
| bit3 | `PD8` | 1 为按下 |
| bit4 | `PD9` | 1 为按下 |
| bit5 | `PD10` | 1 为按下 |
| bit6..7 | 保留 | 忽略 |

### `switch_bits`

| 位 | 遥控引脚 | 状态 |
| --- | --- | --- |
| bit0 | `PE4` | 1 为闭合 |
| bit1 | `PE3` | 1 为闭合 |
| bit2 | `PE1` | 1 为闭合 |
| bit3 | 保留，固定为 `0` | 忽略 |
| bit4 | `PD6` | 1 为闭合 |
| bit5 | `PD5` | 1 为闭合 |
| bit6..7 | 保留 | 忽略 |

空闲状态、`sequence=0` 的完整测试帧为：

```text
A5 5A 02 01 02 00 00 00 1C
```

其中 `1C` 是前面字段计算得到的 CRC8。可先用此帧检查第二主控解析器。

## 6. 第二主控解析要求

串口是连续字节流，不能假设一次 DMA 或中断正好收到一帧。接收程序按以下顺序处理：

1. 在字节流中寻找连续帧头 `A5 5A`。
2. 收到 `payload_len` 后计算总长度 `7 + payload_len`。
3. 拒绝超过接收缓冲区的长度。
4. 收满后先校验 CRC，再检查 `target_id=0x02`、`type=0x01`、`payload_len=2`。
5. 校验通过后一次性更新按键和开关状态。
6. 建议连续 `200 ms` 没有合法帧时清除输入并停止对应机构。

`sequence` 可用于观察丢帧，但当前协议没有应答和重传。遥控输入是周期状态量，后续合法帧会覆盖旧状态。

## 7. 本机底盘控制规则

本机帧长度为 13 字节，payload 固定 6 字节：

| payload 字节 | 内容 |
| --- | --- |
| 0 | 左摇杆 X |
| 1 | 左摇杆 Y |
| 2 | 右摇杆 X |
| 3 | 右摇杆 Y |
| 4 bit0..5 | 本机六键 |
| 4 bit6 | 左肩键 |
| 4 bit7 | 右肩键 |
| 5 bit0 | `PE0` 拨动开关，1 为闭合 |
| 5 bit1..7 | 保留，固定为 `0` |

摇杆居中、按键和 PE0 均松开、`sequence=0` 的本机测试帧为：

```text
A5 5A 01 01 06 00 80 80 80 80 00 00 3A
```

仅将 PE0 闭合后，最后一个 payload 字节变为 `01`，CRC 相应变为 `3D`：

```text
A5 5A 01 01 06 00 80 80 80 80 00 01 3D
```

摇杆输出范围为 `0..255`，中心为 `128`。物理方向是左推/上推为小值，右推/下推为大值；本机接收端转换为底盘坐标：

- 右推：`+vx`，车向右移动。
- 左推：`-vx`，车向左移动。
- 上推：`+vy`，车向前移动。
- 下推：`-vy`，车向后移动。

左摇杆最大平移速度为 `0.150 m/s`。只有左摇杆 X、Y 都回到 `128` 后，右摇杆才生效，右摇杆最大平移速度为 `0.050 m/s`。斜向输入会做矢量限幅。

左肩键输出 `+0.010 rad/s`，车逆时针旋转；右肩键输出 `-0.010 rad/s`，车顺时针旋转；两肩键同时按下时旋转速度为零。收到过本机帧后连续 `200 ms` 没有合法帧，底盘执行停车。

## 8. 遥控输入处理

- 数字按键和开关连续稳定约 `10 ms` 后才更新。
- 肩键映射范围为 `0..1000`，按下阈值 `600`，释放阈值 `550`。
- 摇杆中心死区为 `128 +/- 10`，死区内统一输出 `128`。
- 上电蜂鸣器响三次；数字按键或开关状态变化响一次；摇杆和肩键变化不响。

摇杆 12 位 ADC 标定值：

| 轴 | 最小值 | 中心值 | 最大值 |
| --- | ---: | ---: | ---: |
| 右 X | 10 | 2103 | 4080 |
| 右 Y | 10 | 1960 | 4080 |
| 左 X | 10 | 2142 | 4080 |
| 左 Y | 10 | 1964 | 4080 |

肩键原始 ADC 的松开区间为 `2030..2070`，两端满行程标定值为 `675` 和 `3722`。

## 9. 联调步骤

1. 遥控器上电，确认蜂鸣器响三次。
2. 接收端观察 `remote_link_valid_frames` 持续增加，`remote_link_crc_errors` 不应持续增加。
3. 保持第二主控断开，操作摇杆、肩键、左侧六键和 PE0，确认 `remote_link_data` 对应字段正确更新。
4. 接入第二主控，确认其接收帧头为 `A5 5A`、目标 ID 为 `02`、总长度为 9 字节。
5. 逐个操作右侧六键和五个第二主控开关，核对第 5 节位号；再单独操作 PE0，确认它只出现在 ID 1 帧。
6. 关闭遥控器，确认两块主控均在设定超时后清除输入或停车。

本机可观察的通信变量：

| 变量 | 含义 |
| --- | --- |
| `remote_link_rx_bytes` | LoRa 串口累计接收字节数 |
| `remote_link_valid_frames` | CRC 和字段均正确的 ID 1 累计帧数 |
| `remote_link_crc_errors` | CRC、长度或字段错误累计次数 |
| `remote_link_forward_errors` | 通过 USART2 向第二主控转发失败次数 |
| `remote_link_lora_config_status` | 接收端 E32 配置状态，`2` 表示就绪 |
| `remote_link_data` | 最近一次 ID 1 帧解析结果，PE0 位于 `switch_state[3]` |

发送端可观察 `remote_lora_config_status`、`remote_lora_config_attempts`、`remote_lora_config_readback[6]`、`remote_tx_frame_count`、`remote_tx_busy_skip_count`、`remote_tx_config_skip_count` 和 `remote_tx_error_count`。

## 10. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 第二主控完全收不到数据 | 串口是否为 2 Mbps、TX/RX 是否交叉、是否共地 |
| 能收到但始终无法验帧 | CRC 是否从 `target_id` 开始、是否错误包含了帧头 |
| 偶尔错位 | 是否按连续字节流查找帧头，而不是依赖单次 DMA 长度 |
| 按键位顺序不对 | 对照第 5 节 bit0..bit5，不要按 GPIO 编号重新排序 |
| 本机有数据但第二主控没有 | 检查 `remote_link_forward_errors` 和 USART2 |
| 遥控关闭后机构保持动作 | 第二主控未实现通信超时清零 |

USART1 的 VOFA JustFloat 输出仅用于遥控器本地 ADC 调试，不属于上述控制协议。
