# H723VGT6 上层控制台

这是 `H723VGT6-上层` 的 PC 端控制程序，使用 Tkinter 绘制界面，使用 `pyserial` 访问 CH340N 对应的虚拟串口。界面分为三个可切换页面：

- 机械臂：达妙 J4310 + 两个 M3508
- 开关门：一个 M2006
- 夹爪：一个 M2006

## 启动

Windows 上双击 `启动上位机.bat`，或在当前目录运行：

```powershell
python -m pip install -r requirements.txt
python main.py
```

Python 3.10 或更高版本可用。串口为 UART4，参数为 `115200 8N1`。浏览器不参与串口访问，因此不需要额外的本地服务器。

## 目标与软件零位

上位机保留“允许输出”“发送目标”“停止发送”控件。勾选“允许输出”只修改本地授权状态，不会向板端发送当前位置，也不会使电机开始控制；数值输入框只更新待发送参数，必须点击“发送目标”才会下发。位置滑块是直接控制入口：按下滑块会自动允许对应电机输出并立即发送目标，拖动期间每 50 ms 刷新一次，松开时再发送最终目标并保持。所有位置滑块范围均为 `-360 deg..+360 deg`。开关门 M2006（FDCAN3 ID 1）和夹爪 M2006（FDCAN3 ID 2）采用严格单页控制：发送或拖动其中一个时，只携带该节点的使能位，并自动撤销另一个页面的输出勾选。两个 M3508 保留各自独立的位置目标输入；两台电机共用同步滑块，滑块值为 `x` 时直接向 M3508 #1 下发 `-x`、向 M3508 #2 下发 `x`。连接期间的握手与心跳只维护串口链路，不包含电机目标或使能位。按下空格键或点击“急停”按钮都会立即发送独立的急停命令并清除全部输出使能；按住空格不会重复发送。

J4310 和两台 M2006 的角度输入旁各有联动滑块；两台 M3508 使用两个独立目标输入和一个公共同步滑块。J4310 的 MIT 协议位置能力范围仍为 `-12.5..+12.5 rad`，但上位机位置控件限制为 `-360 deg..+360 deg`。J4310 操作行实时显示当前反馈的输出轴编码器角度，板端单位 `rad`，界面转换为 `deg`；反馈超过 50 ms 未更新时显示 `-- deg`。点击“永久标定”会先停止所有电机，再向 J4310 发送保存当前位置为永久零位的 `0xFE` 动作，并在运行日志显示板端成功或失败回执。

J4310 旁的“重启归零”开关会把配置保存到 H723 外部 W25Q Flash。开关开启后，H723 首次收到 J4310 反馈以及检测到电机反馈断开后重新出现时，会用带速度和加速度限制的双向连续位置轨迹把 J4310 输出轴平滑带回永久零位 `0 rad`，归零后保持零位。开关关闭、急停或手动 J4310 控制会立即释放自动归零控制。开启开关本身不会移动当前在线电机，必须等下一次 H723/J4310 重启或反馈重连。按钮在握手后即可点击；若板端未上报该功能或 Flash 未就绪，界面会明确显示原因且不会发送设置。

M3508 和 M2006 的上位机目标范围为 `-360 deg..+360 deg`。H723 每次重新上电、复位或初始化驱动后只接收电机 CAN 反馈，不发送使能、电流、速度、位置或停止帧，也不通过零电流帧执行上电测试。每台电机必须在转速接近静止时收到连续 5 帧稳定的转子编码器反馈，随后把最后一帧的当前位置保存为该电机的软件零点。C620/C610 不直接反馈减速器输出轴的绝对角度，板端通过后续转子编码器累计变化量除以减速比，得到相对该软件零点的输出轴角度。发送 `0 deg` 表示回到本次 H723 上电时建立的基准位置；发送 `10 deg` 表示从该基准位置转到输出轴 `+10 deg`。电机反馈短暂中断、上位机连接和勾选允许输出都不会重新标定，只有 H723 重新初始化驱动或者显式执行零点命令才会改变软件零点。软件零点不写入 Flash，因为本需求是 H723 每次重新上电都用当时位置建立新基准。J4310 不使用这一上电软件零点。

上位机分别显示 M3508 #1、M3508 #2、开关门 M2006 和夹爪 M2006 的“当前输出轴角度”“相对标定零点角度”“是否标零”及“反馈状态”。当前输出轴角度由标定零点对应的输出轴角度叠加累计相对角度得到，避免转子单圈编码器回绕后显示跳变；尚未标零时暂按当前转子单圈角度除以减速比显示，相对标定零点角度显示为 `-- deg`。四台电机通过独立短帧轮询刷新，单台约 `20 Hz`，避免无线串口截断原有长状态帧。若显示“未收到诊断，请烧录新固件”，说明 H723 仍运行旧版状态协议。

两台 C620 必须工作在 CAN 模式、使用 1 Mbps，并分别设置为 ID 1 和 ID 2；正常反馈标准帧 ID 分别为 `0x201` 和 `0x202`。若两台电调使用相同 ID，它们会读取同一个 `0x200` 控制槽位，并可能因同时发送相同仲裁 ID、不同数据而产生 CAN 错误。新版 DJI 短帧会回传三路 FDCAN 原始收帧计数；无反馈提示会区分 FDCAN2 总线无帧和总线上有帧但缺少当前电机反馈 ID。

板端初始化、上位机连接、握手、心跳和仅勾选“允许输出”都不会启动角度控制。输入框目标只有在勾选对应输出后点击“发送目标”才会下发；拖动位置滑块则会自动允许对应输出并直接控制电机。点击“停止发送”、断连或命令超时会退出对应输出。

J4310 的 MIT `p_des`/`v_des` 是输出轴位置/速度，协议单位分别为 `rad` 与 `rad/s`；M3508 目标位置由转子角度按 `3591/187` 减速比换算为输出轴角度，M2006 按 `36` 减速比换算。J4310 的位置、速度、Kp、Kd、tau 和力矩限幅会在拖动位置滑块或点击“发送目标”时写入扩展位置帧；M3508/M2006 也通过这两种显式操作发送 `0x12` 命令，进入板端“位置环 -> 速度环 -> 电流命令”级联控制。

首次发送目标前必须架空机构、确认机械限位和急停链路有效。串口断开后不再有心跳，板端会在超过 200 ms 后停止远程输出。

点击“连接”后，上位机会先发送 `HANDSHAKE (0x03)` 请求（payload 为 ASCII `H723`），并等待板端返回同序列号的 `ACK (0x7E)`（payload 同为 `H723`）。收到匹配 ACK 前界面保持等待状态，不会发送心跳或电机目标；收到 ACK 后会查询一次 Flash 信息，并开始发送空 payload 心跳，仍不会发送电机目标。握手重试始终使用同一个序列号。超过 3 秒仍未响应时，上位机保持串口打开并继续等待。握手成功后若超过 1 秒没有收到板端状态帧，会立即清除输出使能并自动回到握手状态，以适应主控掉电重启。

界面中的“断连”只断开控制会话、停止所有周期发送，不关闭无线 DAP 的 CDC 串口；再次点击“连接”会复用同一个串口句柄并重新握手。这样主控和接收端无线 DAP 一起掉电、再上电时，不需要给电脑侧发送端重新上下电。电脑侧发送 DAP 被物理拔出或发生串口读写错误时，上位机会立即释放已经失效的 Windows 串口句柄并恢复“连接”按钮；重新插入后可直接再次连接，若 Windows 分配了新的 COM 号则先点击“刷新”。退出上位机，或者断连后选择其他串口/波特率再连接时，也会真正关闭原串口。

Horco 无线 DAP 的无线模块为半双工。进行 Keil 下载或调试时，DAP 会暂时关闭 CDC 虚拟串口，并在超过其 `CDC After DAP` 时间没有新调试数据后恢复。调试期间不要反复打开、关闭 COM 口；需要使用上位机时，应先退出 Keil Debug，并等待主机蓝灯和从机绿灯进入呼吸状态。升级到本版本后首次运行前，如果发送端已经处于无法透传的旧状态，仍需最后重启发送端一次；之后按上述流程不会再因界面断连而反复开关 CDC。

## PC 二进制协议

帧格式与 `User/Driver/PcLink/pc_protocol.c` 一致，所有多字节字段为小端：

```text
A5 5A | version(u8) | type(u8) | sequence(u16) | length(u16) |
payload(length) | CRC16(u16)
```

CRC16 为 Modbus CRC（初值 `0xFFFF`，多项式 `0xA001`），覆盖 `version` 到 payload 的全部字节。

| 类型 | 值 | 说明 |
| --- | ---: | --- |
| HEARTBEAT | `0x01` | 空 payload，维持远程链路 |
| ESTOP | `0x02` | payload 为 `01`，进入急停 |
| HANDSHAKE | `0x03` | payload 为 ASCII `H723`，请求建立控制链路 |
| UPPER_CMD | `0x10` | 原有 V3 速度命令，保持兼容 |
| UPPER_POSITION_CMD | `0x12` | 位置命令，兼容 34 字节，当前发送 122 字节扩展 payload |
| MOTOR_ACTION | `0x13` | J4310 维护动作；保存零点为 3 字节 payload，重启归零配置为 4 字节 `action, can_bus, node_id, enabled` |
| FLASH_INFO_REQUEST | `0x14` | 空 payload；无需握手，单次请求外部 Flash 信息 |
| ROBOT_STATE | `0x20` | 当前为 84 字节：基础状态、J4310 位置、RX/TX 诊断、自动归零配置和运行状态；上位机兼容旧版 20/25/50/80/89/101 字节 |
| DJI_TELEMETRY | `0x22` | 28 字节：单台 DJI 诊断和 3 路 FDCAN 原始 RX 计数；四台轮询发送 |
| FLASH_INFO | `0x23` | 20 字节 Flash 初始化结果、JEDEC ID 和容量信息；序列号与查询请求一致 |
| ACK | `0x7E` | 握手确认：序列号与请求一致，payload 为 ASCII `H723` |

`FLASH_INFO (0x23)` payload 为 `<BBIIIHI`：`init_status(u8)`、`initialized(u8)`、`jedec_id(u32)`、`capacity_kb(u32)`、`sector_count(u32)`、`page_size_byte(u16)`、`sector_size_byte(u32)`。查询无需控制会话，只读取启动阶段保存的初始化结果，不会重新访问 SPI，也不会激活会话、刷新电机控制超时或启动周期遥测。界面会显示 `w25q_init_status` 的数值和枚举名，例如 `3 W25Q_ERROR_UNSUPPORTED_DEVICE`。

兼容位置命令 payload 为 `u16 enable_mask + 8 个 little-endian float`（34 字节）。当前上位机发送扩展位置命令，payload 为 `u16 enable_mask + 30 个 little-endian float`（122 字节）：

| 偏移 | 字段 | 单位 |
| ---: | --- | --- |
| 0 | 使能位：bit0 旧机械臂组合，bit1 开关门，bit2 夹爪，bit3 旧四路 DJI 同步，bit4 仅 J4310，bit5 仅两台 M3508，bit6 显式停止 J4310 | - |
| 2 | J4310 目标位置（输出轴角度） | rad |
| 6 | J4310 目标角速度（输出轴） | rad/s |
| 10 | J4310 基准 Kp | - |
| 14 | J4310 基准 Kd | - |
| 18 | M3508 #1 位置（输出轴角度） | rad |
| 22 | M3508 #2 位置（输出轴角度） | rad |
| 26 | 开关门 M2006 位置（输出轴角度） | rad |
| 30 | 夹爪 M2006 位置（输出轴角度） | rad |

扩展位置命令的完整浮点顺序如下；与兼容布局相比，M3508/M2006 位置字段后移到浮点序号 6..9：

| 浮点序号 | 字段 | GUI 单位 |
| ---: | --- | --- |
| 4 | J4310 `tau` | Nm |
| 5 | J4310 力矩限幅 | Nm |
| 6..9 | M3508 #1/#2、开关门、夹爪位置 | rad |
| 10..14 | M3508 速度环 Kp/Ki/Kd/积分限幅/输出限幅 | DJI_H723_VOFA GUI 单位 |
| 15..19 | M3508 位置环 Kp/Ki/Kd/积分限幅/输出限幅 | DJI_H723_VOFA GUI 单位 |
| 20..24 | M2006 速度环 Kp/Ki/Kd/积分限幅/输出限幅 | DJI_H723_VOFA GUI 单位 |
| 25..29 | M2006 位置环 Kp/Ki/Kd/积分限幅/输出限幅 | DJI_H723_VOFA GUI 单位 |

`0x10` 速度命令使用同样的偏移，但偏移 18/22/26/30 解释为 `rad/s`，并由原有速度模式处理。

## J4310 MIT 参数

板端 J4310 使用标准 8 字节 MIT CAN 帧，CAN 标准 ID 为电机逻辑 ID `0x06`，反馈 Master ID 为 `0x16`。`p_des` 与 `v_des` 均以 J4310 输出轴为基准，参数映射为：

上位机可编辑并发送全部 MIT 参数：`p_des`、`v_des`、`Kp`、`Kd`、前馈 `tau` 和力矩限幅。`tau` 默认 `0 Nm`，力矩限幅默认 `10 Nm`；后两项分别对应 MIT 帧力矩字段和板端软件安全裁剪范围。软件力矩限幅只裁剪 `tau`，不会改变协议映射；MIT 命令编码和反馈解码始终使用与达妙调试助手一致的固定 `TMAX=10 Nm`。

H723 握手不会自动使能 J4310。勾选 GUI 的“使能 J4310 输出”只建立本地发送授权；点击 J4310 的“发送目标”或直接拖动 J4310 滑块后，上位机才下发当前位置，板端随后先发标准帧 `ID=0x006 / FF FF FF FF FF FF FF FC`。板端不再把 HAL TX 入队成功当成电机已使能；只有收到本次使能请求之后的 `data[0]高四位=0x1` 才开始发 MIT 控制帧。反馈仍为 `0x0` 时每 20 ms 限频重发 `0xFC`。

机械臂页只显示 J4310 反馈状态和 H723 Flash 是否就绪，不再显示 TX/RX 计数、最近 CAN 帧或拒绝明细。`0x0` 为未使能，`0x1` 为已使能，`0x2/0x3/0x5/0x7/0x8..0xE` 为电机异常或故障。

| 字段 | 范围 | 位宽 | 打包位置 |
| --- | ---: | ---: | --- |
| 目标位置 p | `-12.5 .. +12.5 rad` | 16 | data[0:1] |
| 目标速度 v | `-30 .. +30 rad/s` | 12 | data[2:3] |
| Kp | `0 .. 500` | 12 | data[3:4] |
| Kd | `0 .. 5` | 12 | data[5:6] |
| 前馈力矩 τ | `-10 .. +10 Nm` | 12 | data[6:7] |

发送 `FC` 为使能、`FD` 为失能、`FB` 为清故障、`FE` 为保存零点；正常位置控制帧始终按 MIT 的 `p | v | Kp | Kd | τ` 打包。当前上位机不提供 `FE` 永久零点命令入口。界面默认 τ=0。

## 电机错误日志

J4310 回包中的过压、欠压、过流、MOS/线圈过温、通信丢失和过载故障，以及 J4310、M3508、M2006 的反馈超时，都会由板端生成 `0x7F` 错误事件。上位机将这些故障以及电机动作失败统一追加写入 `上层分支/电机日志.log`，每条记录包含型号、FDCAN、节点 ID、错误或动作状态、板端毫秒时间戳和 PC 本地时间；普通电机反馈和成功的电机动作不会写入该日志。

## DJI_H723_VOFA GUI 参考 PID 参数

页面中的 M3508/M2006 参数表使用参考工程 `DJI_H723_VOFA` 的 GUI 单位，所有输入项均可修改，并随扩展 `0x12` 位置命令发送到 H723；板端收到后再换算为驱动内部单位。

### M2006 / C610（GUI 单位）

| 环路 | Kp | Ki | Kd | 积分限幅 | 输出限幅 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 速度环 | 350 | 250 | 0 | 0.5 | 10000 |
| 位置环 | 220 | 500 | 5 | 0.002 | 50 rpm |

板端正式协议解析层的换算关系如下。令 `rpm_to_rad_s = 2π / 60`、`rad_s_to_rpm = 60 / (2π)`，电流缩放因子为 `M3508: 20 / 16384 A/raw`、`M2006: 10 / 10000 A/raw`：

- 速度环：`Kp/Ki/Kd_board = GUI × current_scale × rad_s_to_rpm`，`I_limit_board = GUI × rpm_to_rad_s`，`output_limit_board = GUI × current_scale`。
- 位置环：`Kp/Ki/Kd_board = GUI × rpm_to_rad_s`，`I_limit_board` 保持不变，`output_limit_board = GUI × rpm_to_rad_s`。

上面的换算由 `User/Application/Communication/upper_pc_link.c` 执行；不能把 GUI 数值直接填入 `upper_config.h`，否则控制量量纲不一致。
