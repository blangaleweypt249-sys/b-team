# 串口通信协议

`competition_gateway` 是上位机侧唯一允许打开串口设备的 C++ ROS 2 节点。它订阅定位与视觉结果后向 STM32 发送感知帧和位置帧；STM32 回传自身状态帧。底盘、机械臂、CAN、VESC 和状态机的实时控制仍在 STM32 板端执行。

## 参数与接口

|   项目   | 默认值 | 说明 |
| ------- | --- | --- |
|  串口设备  | `/dev/ttyUSB0` | 在 `competition_gateway/config/serial_gateway.yaml` 中配置 |
|    波特率 | `115200` | 支持 9600、57600、115200、460800、921600 |
| 发送周期 | 10 ms | 感知帧与位置帧交替发送，共 100 Hz（每种帧 50 Hz） |
| 定位输入 | `/competition/field_pose` | `geometry_msgs/PoseStamped` |
| 球位置输入 | `/perception/ball_position` | `geometry_msgs/PointStamped` |
| 块位置输入 | `/perception/block_position` | `geometry_msgs/PointStamped` |
| 控制器在线状态 | `/competition/serial/controller_connected` | `std_msgs/Bool` |
| 控制器状态 | `/competition/serial/controller_state` | `std_msgs/UInt8` |
| 控制器错误 | `/competition/serial/controller_error` | `std_msgs/UInt8` |

## 校验机制

所有帧使用 **CRC16-CCITT**（多项式 `0x1021`，初始值 `0xFFFF`，小端序）进行校验。CRC16 覆盖范围为帧类型字节到最后一个数据字节（不含帧头、CRC 本身和帧尾）。相比 8 位累加和，CRC16 能检测字节交换、双位错误和突发错误。

## 时间戳

感知帧和位置帧包含 4 字节 `timestamp_ms` 字段（`uint32_t`，小端序），表示数据生成时刻的毫秒时间戳。STM32 可通过以下方式使用时间戳：

- **检测数据新鲜度**：比较连续帧的时间戳间隔，判断上位机是否在持续发送有效数据。
- **测量通信延迟**：用本地接收时刻减去 `timestamp_ms`（需时钟同步或仅用于相对比较）。
- **丢帧检测**：配合 `sequence` 字段，区分"帧丢失"和"数据未更新"。

## 上位机到 STM32：感知帧

固定长度为 37 字节，帧类型 `0x10`。包含当前跟踪块和球的位置数据，块在球前面。所有 `float` 使用 IEEE 754 单精度格式，字节序为小端序。

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `0xAA` | 帧头 0 |
| 1 | 1 | `0x55` | 帧头 1 |
| 2 | 1 | `0x10` | 感知帧类型 |
| 3 | 1 | `sequence` | 每发送一帧递增，溢出后从 0 开始 |
| 4 | 1 | `flags` | 位 0：块有效；位 2：球有效 |
| 5 | 4 | `timestamp_ms` | 数据生成时间戳（毫秒，uint32，小端序） |
| 9 | 4 | `block_x_m` | 当前跟踪块位置 X，单位 m |
| 13 | 4 | `block_y_m` | 当前跟踪块位置 Y，单位 m |
| 17 | 4 | `block_z_m` | 当前跟踪块位置 Z，单位 m |
| 21 | 4 | `ball_x_m` | 球位置 X，单位 m |
| 25 | 4 | `ball_y_m` | 球位置 Y，单位 m |
| 29 | 4 | `ball_z_m` | 球位置 Z，单位 m |
| 33 | 2 | `crc16` | 偏移 2 至 32 的 CRC16-CCITT 校验值（小端序） |
| 35 | 1 | `0x0D` | 帧尾 0 |
| 36 | 1 | `0x0A` | 帧尾 1 |

若数据超过 `data_timeout_ms` 未更新，对应有效位清零；下位机必须忽略无效位对应的数据。

## 上位机到 STM32：位置帧

固定长度为 29 字节，帧类型 `0x11`，与感知帧在同一串口交替发送。只包含机器人赛场坐标和偏航角。

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `0xAA` | 帧头 0 |
| 1 | 1 | `0x55` | 帧头 1 |
| 2 | 1 | `0x11` | 位置帧类型 |
| 3 | 1 | `sequence` | 每发送一帧递增，溢出后从 0 开始 |
| 4 | 1 | `flags` | 位 0：定位有效 |
| 5 | 4 | `timestamp_ms` | 数据生成时间戳（毫秒，uint32，小端序） |
| 9 | 4 | `field_x_m` | 赛场坐标 X，单位 m |
| 13 | 4 | `field_y_m` | 赛场坐标 Y，单位 m |
| 17 | 4 | `field_z_m` | 赛场坐标 Z，单位 m |
| 21 | 4 | `field_yaw` | 机器人偏航角yaw（弧度，初始为 0） |
| 25 | 2 | `crc16` | 偏移 2 至 24 的 CRC16-CCITT 校验值（小端序） |
| 27 | 1 | `0x0D` | 帧尾 0 |
| 28 | 1 | `0x0A` | 帧尾 1 |

若定位数据超过 `data_timeout_ms` 未更新，对应有效位清零。

## STM32 到上位机：状态帧

固定长度为 9 字节。下位机建议以不低于 10 Hz 的频率回传状态帧；超过 `controller_timeout_ms` 未收到有效帧时，上位机发布控制器离线。

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `0x55` | 帧头 0 |
| 1 | 1 | `0xAA` | 帧头 1 |
| 2 | 1 | `0x20` | 状态帧类型 |
| 3 | 1 | `state` | 板端机器人状态机状态 |
| 4 | 1 | `error` | 板端错误码 |
| 5 | 2 | `crc16` | 偏移 2 至 4 的 CRC16-CCITT 校验值（小端序） |
| 7 | 1 | `0x0D` | 帧尾 0 |
| 8 | 1 | `0x0A` | 帧尾 1 |

## STM32 实现要求

1. 使用环形缓冲区接收字节流，逐字节查找帧头，不能假设一次 UART DMA 回调恰好收到一帧。
2. 先检查帧头、类型、帧尾和 CRC16，再使用有效载荷。
3. 收到无效定位或视觉标志时，清除对应目标，不得继续沿用上一次的有效数据。
4. 可利用 `timestamp_ms` 判断数据新鲜度，丢弃过时数据。
5. 串口超时只能进入板端安全状态或降级模式，不得由上位机脚本接管核心闭环。
6. CAN/VESC 指令、PID 与机器人状态机保留在 STM32 工程中，不能放入本 C++ 网关。

## CRC16-CCITT 参考实现

STM32 端可使用以下 C 代码实现 CRC16 校验：

```c
#include <stdint.h>
#include <stddef.h>

uint16_t crc16_ccitt(const uint8_t *data, size_t size)
{
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < size; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (int j = 0; j < 8; j++) {
            if (crc & 0x8000) {
                crc = (crc << 1) ^ 0x1021;
            } else {
                crc <<= 1;
            }
        }
    }
    return crc;
}
```
