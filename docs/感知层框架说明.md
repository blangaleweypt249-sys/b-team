# 感知层代码框架说明

## 1. 当前范围

感知层由 `fyt_pos`、`ball_perception`、`common_launch_pkg` 和 `competition_gateway` 四个包组成，负责：

- 激光里程计定位：将 FAST-LIO 里程计转换为比赛场地坐标
- 场地区域分类：判定机器人所在功能区域
- USB 相机图像采集与发布
- MID360 雷达点云订阅
- YOLOv8-seg 金球检测与分割
- 相机-雷达融合测距（点云投影 + mask 搜索）
- 球 3D 位置发布
- 串口网关：将感知数据封装为固定帧发送给 STM32
- 集成启动：一键启动所有感知节点

本轮不包含：
- 完整 ROS 工作区编译与依赖说明（见 `系统说明.md`）
- GPU 加速推理优化
- 多球识别与跟踪
- 动态参数标定

代码调用方向固定为：

```
common_launch_pkg (集成启动)
  ├── fast_lio: 里程计 → /Odometry
  ├── fyt_pos (Python)
  │   ├── field_localizer: 里程计→场地坐标 → /competition/field_pose
  │   └── field_visualizer: RViz 可视化 → /competition/field_markers
  ├── ball_perception (Python)
  │   ├── usb_camera_node: 相机采集 → /camera/image_raw
  │   └── ball_distance_node: YOLO+点云融合 → /perception/ball_position
  └── competition_gateway (C++): 话题订阅 → 串口帧 → STM32
```

## 3. 代码边界

### 3.1 命名规范

- 普通变量使用小写加下划线：`latest_image`, `ball_3d_lidar`
- 常量全部大写或 `k_` 前缀：`k_tx_frame_size`, `PERCEPTION_FIELD_POSE_VALID`
- 结构体和枚举类型使用 `_t` 后缀：`perception_data_t`, `controller_status_t`
- C++ 函数使用 `模块_动作()` 形式：`SerialGateway_Open()`, `SerialProtocol_Checksum()`
- Python 类使用大驼峰：`USBCameraNode`, `BallDistanceNode`

### 3.2 文件组织

- 每个功能使用独立 `.py` 或 `.cpp/.hpp`
- Python `.py` 文件顺序：导入 → 常量 → 类 → 函数 → main
- C++ `.cpp` 文件顺序：include → anonymous namespace → 全局函数 → 成员函数

### 3.3 参数管理

所有参数集中在 `config/perception_params.yaml`：
- 相机内参：`fx`, `fy`, `cx`, `cy`, `d0`-`d4`
- 外参：`extrinsic_x/y/z`, `roll/pitch/yaw`
- 滤波：`min_distance`, `max_distance`, `distance_alpha`
- 检测：`model_path`, `conf_threshold`

禁止在业务函数中散落魔法数字。

### 3.4 数据有效期

- 感知帧超时 `data_timeout_ms = 200ms`
- 控制器超时 `controller_timeout_ms = 500ms`
- 发送周期 `send_period_ms = 20ms` (50Hz)

数据超过超时时间后，对应有效位清零，STM32 不得继续使用旧数据。

## 4. 数据流与话题

### 4.1 话题清单

| 话题 | 类型 | 发布者 | 订阅者 |
|------|------|--------|--------|
| `/Odometry` | `nav_msgs/Odometry` | FAST-LIO | `field_localizer` |
| `/competition/field_pose` | `geometry_msgs/PoseStamped` | `field_localizer` | `serial_gateway`, `field_visualizer` |
| `/competition/current_zone` | `std_msgs/String` | `field_localizer` | 调试用 |
| `/competition/field_markers` | `visualization_msgs/MarkerArray` | `field_visualizer` | RViz |
| `/camera/image_raw` | `sensor_msgs/Image` | `usb_camera_node` | `ball_distance_node` |
| `/camera/camera_info` | `sensor_msgs/CameraInfo` | `usb_camera_node` | 调试用 |
| `/livox/lidar` | `sensor_msgs/PointCloud2` | MID360 驱动 | `ball_distance_node` |
| `/perception/ball_position` | `geometry_msgs/PointStamped` | `ball_distance_node` | `serial_gateway` |
| `/perception/ball_overlay` | `sensor_msgs/Image` | `ball_distance_node` | 调试用 |
| `/perception/ball_distance` | `std_msgs/Float32` | `ball_distance_node` | 调试用 |

### 4.2 定位流程

```
FAST-LIO 里程计 (/Odometry)
  ↓
field_localizer:
  1. 累积 30 帧建立场地原点 (启动时)
  2. 里程计→车体中心外参换算
  3. 旋转到场地坐标系
  4. 起点角落变换 (bottom_left/bottom_right)
  5. 区域分类 + 越界检测
  ↓
发布 /competition/field_pose (场地坐标系)
发布 /competition/current_zone (区域名称)
```

### 4.3 融合测距流程

```
相机图像 → YOLOv8-seg → 获取球分割 mask
          ↓
MID360 点云 → 外参变换 → 投影到图像平面
          ↓
mask 区域内搜索投影点 → 取深度中值 → EMA 平滑
          ↓
发布 /perception/ball_position (雷达坐标系)
```

### 4.4 坐标转换

```
雷达坐标系 (ROS标准):
  X前, Y左, Z上

相机坐标系 (OpenCV标准):
  Z前, X右, Y下

变换关系:
  相机在雷达右侧 198mm
  T_lidar_to_cam = R_axis @ R_user, t = (0, -0.198, 0)
```

## 6. 串口协议

### 6.1 感知帧格式（32 字节）

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0-1 | 帧头 | `0xAA 0x55` |
| 2 | 帧类型 | `0x10` |
| 3 | 序号 | 递增，溢出从 0 开始 |
| 4 | 有效位 | bit0: 定位有效, bit1: 球位置有效 |
| 5-16 | 定位坐标 | `field_x_m`, `field_y_m`, `field_z_m` (float32) |
| 17-28 | 球位置 | `target_x_m`, `target_y_m`, `target_z_m` (float32) |
| 29 | 校验 | 偏移 2-28 累加和 |
| 30-31 | 帧尾 | `0x0D 0x0A` |

所有 float 使用 IEEE 754 单精度，小端序。

### 6.2 STM32 状态帧（8 字节）

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0-1 | 帧头 | `0x55 0xAA` |
| 2 | 帧类型 | `0x20` |
| 3 | 状态 | `state` |
| 4 | 错误码 | `error` |
| 5 | 校验 | 偏移 2-4 累加和 |
| 6-7 | 帧尾 | `0x0D 0x0A` |

### 6.3 串口配置

| 参数 | 值 |
|------|-----|
| 设备 | `/dev/ttyUSB0` |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 流控 | 无 |

## 8. 代码规范

### 8.1 Python 规范

- 使用 ROS2 Python API (`rclpy`)
- 回调函数只更新缓存，定时函数做融合
- 使用 `CvBridge` 转换图像格式
- 使用 `sensor_msgs_py.point_cloud2` 解析点云
- 参数通过 `declare_parameter` / `get_parameter` 管理

### 8.2 C++ 规范

- 使用 ROS2 C++ API (`rclcpp`)
- 串口操作在独立线程/定时器中
- 使用 `std::lock_guard` 保护共享数据
- 帧编码/解码分离，便于测试
- 异常捕获后发布错误状态，不崩溃

### 8.3 日志输出

统一使用 ROS2 日志接口：
- `RCLCPP_INFO`：正常状态
- `RCLCPP_WARN`：可恢复异常（点云为空、检测失败）
- `RCLCPP_ERROR`：严重错误（串口打开失败、帧校验失败）

## 9. 集成启动

使用 `common_launch_pkg` 一键启动所有感知节点：

```bash
ros2 launch common_launch_pkg common_launch.py
```

启动顺序（按依赖关系）：
1. FAST-LIO 里程计节点（提供 `/Odometry`）
2. `fyt_pos` 定位节点（依赖里程计）
3. `ball_perception` 球感知节点（依赖相机和雷达）
4. `competition_gateway` 串口网关（依赖所有感知数据）

单独启动各包：
```bash
# 仅定位
ros2 launch fyt_pos fyt_pos.launch.py

# 仅球感知
ros2 launch ball_perception perception_launch.py

# 仅串口网关
ros2 run competition_gateway serial_gateway
```

## 10. 实施原则

1. **数据有效期优先**：超时数据立即失效，有效位清零，不依赖旧数据控制。
2. **单一数据源**：每个物理量只有一个发布者，避免多源冲突。
3. **融合频率固定**：20Hz 融合频率，避免触发抖动。
4. **滤波在融合后**：先获取原始测量，再做 EMA 平滑，便于调试。
5. **坐标系明确**：所有话题明确标注坐标系（雷达系/相机系/比赛场系）。
6. **参数集中管理**：所有标定参数放在 YAML 文件，不硬编码。
7. **通信超时独立处理**：感知超时与控制器超时分开配置。
8. **异常安全**：任一路数据异常不影响其他通道正常工作。
9. **定位初始化安全**：启动时采样 30 帧建立场地原点，采样期间不发布场地位姿。
10. **区域边界独立于功能区**：场地总边界独立配置，越界检测优先于功能区分类。
11. **起点角落可切换**：支持 `bottom_left` 和 `bottom_right` 两种起点配置。
12. **雷达-车体外参必须标定**：`base_to_lidar_x/y/yaw` 必须随雷达安装位置标定。
